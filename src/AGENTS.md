## KEY RULES
- 所有 IPC 走 `window.imageStudio`（contextBridge），绝不直接访问 electron。
- 渲染层禁止使用原生 `window.prompt/confirm/alert`：Electron 不支持 prompt（同步抛 `Error: prompt() is not supported.`，重命名/编辑会静默失败），原生 confirm 在 Windows 有焦点丢失 bug（electron#31917，表现为窗口假死）。需要输入/确认一律走 `components/Dialogs.tsx` 的 `useDialog()`（`requestText`→`Promise<string|null>`、`requestConfirm`→`Promise<boolean>`；取消语义：文本返回 `null`、确认返回 `false`）。`useComposer.ts` 在 `DialogProvider` 之外调用，两个函数必须以参数注入，不能内部 `useDialog()`。
- 新增全屏弹层（`.xxx-modal`）必须同步登记到 `styles.css` 的四处集中列表，否则视觉/动效不一致：①基础遮罩照抄 `.dialog-modal`——`position:fixed; z-index; inset:0; background:var(--overlay-bg); backdrop-filter:blur(var(--overlay-blur))`，**全弹层（`.lightbox`/`.compare-modal`/`.export-modal`/`.dialog-modal`/`.tutorial-modal`）共用 `:root` 的这两个 token 作为单一来源，勿写死数值**（v2.8：用户反馈 10px 模糊度过高，统一为轻量毛玻璃），且 **z-index 必须 ≥50**（高于 header 40 / 固定底栏 45；`.lightbox`/`.compare-modal`/`.export-modal`=50、`.dialog-modal`=60、教程弹层=130）——v3.1 修复：`.lightbox` 自 v1.1 遗留 z-index 20，v2.0 header 升为 fixed z-index 40 拖拽层后 header 盖住预览图上部；**覆盖 header 88px 拖拽盒的弹层还须显式 `-webkit-app-region: no-drag`**（拖拽区按 DOM 前序收集、后声明者胜——Blink `CollectAnnotatedRegions` → Electron `DraggableRegionsToSkRegion`，弹层晚于 header 渲染才能整体挖除；否则覆盖区点击被 OS 当拖窗口），其内交互元素须避开右上原生按钮条（高 `env(titlebar-area-height)`，回退 32px；OS 级区域会吞 DOM 点击，`.lightbox-close` 因此下移到 `calc(env(titlebar-area-height, 32px) + 12px)`）；②700px 窄屏的 padding `2vh 2vw`/卡片 `15px`+`16px` 圆角收缩；③入场动画：**遮罩元素进 `overlay-in`（纯淡入）、卡片元素进 `modal-pop`（缩放上浮）**，切勿把遮罩登记进 `modal-pop`——两条规则同特异性时后定义的 `modal-pop` 会覆盖 `overlay-in`，导致整个遮罩层连带背景一起缩放弹出（v2.8 修复：`.tutorial-center-modal` 名字像卡片、实为遮罩容器（DOM 上是 `.tutorial-modal tutorial-center-modal`，卡片是内层 `.tutorial-center` section），曾被误登记进 modal-pop，表现为点击「新手教程」时遮罩整体弹出）；④`prefers-reduced-motion` 的 `animation: none !important` 组。`.tutorial-shade`（教程聚光灯挖洞遮罩）语义不同，故意不引用 overlay token。
- 需要测试的纯逻辑移入 `src/lib/*.ts`（供 Vitest 覆盖）；React 组件与 `main.tsx` 无测试（现 37 文件 / 439 it；i18n 测试：`i18n.test.ts` 锁定运行时/词典聚合、`error-display.test.ts` 锁定 code 渲染、`ipc-code.test.ts` 锁定 `ipc.*` 词条、`main-i18n.test.ts` 锁定主进程 `mt()`、`i18n-lib-messages.test.ts` 锁定 lib 文案、`template-labels.test.ts` 锁定内置模板 id 本地化）。
- 跨页跳转契约（jump-to-image / jump-to-project）：①`setMode` 不携带 payload——意图先写入独立 state（`galleryTarget: { imageId?: string; projectId?: string } | null`，二选一）再切模式（同 `openLocalAI` 模式）；②`GalleryWorkspace` 消费意图后必须回调 `onFocusConsumed` 清空，否则对同一目标的再次跳转不会生效（图片级 `processedFocusRef` 在 `focusImageId` 清空时复位；项目级 `processedProjectRef` 在 `initialProjectId` 清空时复位；项目级 effect 在 `focusImageId` 存在时直接跳过——图片级优先，所属项目由 resolveFocusLocation 决定）；③悬空 id（删除 / 图库重建）一律 `onNotice` 降级、绝不抛错；④定位页码按目标「所属项目自身列表」计算（`lib/gallery-focus.ts`，排序与 `searchGallery` 一致），`pendingFocus` 落地 effect 必须声明在「筛选条件重置页码」effect 之后（两者同批执行，`setPage` 最后者胜）；⑤无新增 IPC 通道——只用既有 `gallery.loadImage/workspace/search/thumbnail`；⑥项目级跳转不校验项目存在性（选中即消费；项目被删时图库自然显示空列表），带意图挂载以 `useState(initialProjectId ?? "all")` 初始化避免先拉「全部图库」的中间态。
- 统一进度反馈：`TaskProgressEvent`（`shared/types.d.ts`）为核心模型，渲染层经 `ProgressProvider` 单点订阅旧 `image:progress` 与新 `progress:update` 并按 id 归一化；`ProgressBar` 是唯一进度条展示组件（`progress` 有值 = 确定 + 百分比，缺省 = 不定态斜纹；含阶段 i/n 与「已用时」）；本地推理进度留在渲染层（worker 与 renderer 同进程）；真实进度不可知时（增强/反推/长推理）必须缺省 `progress`，禁止伪造百分比。
- 悬浮提示统一走 `components/Tooltip.tsx`：`Tooltip` 只包裹**单个**触发元素（`cloneElement` + 合并既有 handler/ref，零额外 DOM），`InfoHint` 为 16px 问号圆圈按钮（复用 `NavIcon name="circle-question-mark"`，默认 `aria-label`「说明」）；悬停 300ms / 聚焦即时显示，Escape、任意滚动（捕获阶段）、窗口 resize 隐藏；portal 到 `.app`、fixed 定位、`useLayoutEffect` 先测量后显示（不闪烁）、打开期间注入 `role="tooltip"` + `aria-describedby`、`pointer-events:none`、StrictMode 安全；定位纯逻辑在 `lib/tooltip.ts` 的 `resolveTooltipLayout`（above 8px 居中 → 翻转 below → 取较大侧 → 夹回视口不为负；可选 gap/margin 默认 8）。浮层 z-index 80（高于下拉 55 / 对话框 60、低于 toast 90）；新提示一律用它，勿再写原生 `title=`。
- 布局编辑契约（v3.8 双单位）：未建立自定义快照 = 流式渲染（`.composer-modules` 为 `display:contents`，与现状零差异），建立后网格渲染（模块绝对定位、容器显式高度）。**双单位坐标**：x/w 为 64 列（`LAYOUT_COLS`，1 列 = 卡宽/64，随窗口水平自适应）；y/h 为固定 16px 行（`GRID_PX`，垂直与窗口无关、内容高度驱动）；`LAYOUT_MODULES` 的 `minW`/`minH` 为 px 语义（换算列/行由调用方按 `colWidth`/`GRID_PX` 进行），`snapToGrid` 只做垂直行吸附。**尺寸档位**：`LAYOUT_SIZE_THRESHOLDS` + `sizeFlags(id, widthPx)`（widthPx≤0 不触发）；10 个模块根注入 `data-layout-compact`/`data-layout-narrow` → 现为 7 个（软删：prompt-tools / prompt-assistant 已并入 prompt；presets / custom-size 已并入 controls），grid 作用域 CSS 按模块宽度（非视口）响应。通用模块（三模式全可见）坐标/隐藏共享一份（三模式同步），专属模块按出现模式分层（`lib/layout.ts` 的 `effectivePlacement`/`setPlacement`/`setHidden` 自动落到正确层级）；运行行钉底不入模型；放置不允许重叠——**move 拖动 = 纵向推挤**（`resolvePushLayout`：被重叠模块实时下推让位、拖动中全场预览、松手单次 commit 写 moving + 受影响模块（判定 `pushTops[id] !== displayTops[id]`）= 单条撤销、「预览 = 落地」），resize 拖动与导入消解仍走 `findFreeSlot` 避让；显示位置经 `resolveVerticalLayout` 纵向推挤（内容高度动态时不重叠）；**折叠收缩（v3.11.1）**——details 类模块（图反推，`ComposerPanel` 的 `<details>` 挂 `onToggle` 同步）非编辑态折叠时**不注入 min-height**（高度交给内容，避免快照 h 撑出空白；若仍注入，实测恒被撑开、ResizeObserver 永不回调无法自愈），布局解算用实测高度换算的收缩行数，并经受压缩 `compactCollapsedItems`（快照底边之下、横向重叠的模块上移差额）；编辑态恒显示布局真相（快照 h）、拖拽 / 缩放热区与快照一致；`measureInitial` 对 details 一律按折叠态测量（展开高度不进快照）；**垂直缩放下限**（`minResizeHeightPx`）——网格态元素高度 = max(内容自然高度, minHeight 撑开高度)，实测值恒 ≥ 当前高度；拖拽/缩放三处公式的下限一律用会话开始时判定一次的 `DragSession.minHpx`（实测明显顶破撑开高度时取内容自然高度、否则只用 `def.minH`，至少 1 行），绝不读实时实测值（否则形成「只能拉高不能拉矮」棘轮）；网格态模块必须 `margin:0`（绝对定位 top/left 以 margin box 为原点，坐标已承载间距）；网格态模块内装饰文字必须单行化（nowrap + 省略，放不下就隐藏）。**持久化 store v4**（`lib/layout-store.ts` 的 `parseStoredLayout`/`migrateV3ToV4`/`serializeLayoutStore`）：v3→v4 近似迁移须等 `colWidth>0`（真实列宽，否则约 16x 偏差），一次转换全部预设、单次落盘（StrictMode 安全）；localStorage `imagotune:layout:v1`（多方案 store，`default` 方案不可删）。**分享码**：输出 `ITL2:`（只装通用池），`ITL1:` 旧码按当前 `colWidth` 近似换算 y/h 并附「可能需要微调」提示；导入只替换通用并让专属让位。新增可编辑模块必须同时登记 `LAYOUT_MODULES`（id/可见模式/最小尺寸）与模块根元素的 `data-layout-id` 标记，否则不参与布局编辑。
- 模型状态经 `StudioContext` 的 `providers`/`roles` 快照提供，`imageModel`(生图) / `chatModel`(提示词增强) 是派生值（绑定缺失时回退默认），**无 setter**；改动或切换绑定后调用 `refreshSettings()` 重新拉取 `settings:get`。设置写入统一经 `settings.save`（providers 全量 + `removedProviderIds` + roles + autoArchive），现有两个调用者：`SettingsPanel`（携带供应商草稿与删除意图）与 `QuickModelSwitcher`（只改 roles——providers 取快照并剥离 `hasKey`、`removedProviderIds` 恒空，主进程仅对带非空 `apiKey` 的供应商写 keytar，故不动任何凭据）；两者保存成功后都必须 `refreshSettings()`。
